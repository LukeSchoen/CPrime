# Pedantic GCC checks

Input: `corpus.json` selects the retained GCC failure cases under
`corpus/`. Supporting includes are hashed separately and never discovered as
independent tests. Sources and licenses are retained unchanged from revision
`5f6257c26b814de1a14c71b2d3a49291765b6577` of https://github.com/gcc-mirror/gcc.

Run bulk assessment only at the end of a large change requiring deep testing.
Use exact selections while repairing individual failures:

```powershell
./Tests/pedantic/gcc/run.ps1 -List
./Tests/pedantic/gcc/run.ps1 -Select g++.dg/template/access27.C -Out build/gcc-exact
./Tests/pedantic/gcc/run.ps1 -ContinueAfterTimeout -Out build/gcc-checkpoint
```

`-CompilerPath` and `-RuntimeRoot` select the compiler/runtime. Each compiler and
program invocation has a five-second ceiling. Crashes/timeouts fail; no retries
with larger budgets. An empty or unknown selection fails. A new output directory
is generated by default. `compare.ps1 -Baseline <old> -Current <new>` checks for
regressions and lost coverage within the same corpus.

The score is verified passes over the retained checked cases. It starts a new
repair denominator; it is not full GCC or C++ conformance. Cases remain active
when they fail. The runner verifies source/dependency hashes before execution.
`summary.json`, `progress.json`, `metadata.json`, `inputs.json`, and
`results.jsonl` record results and provenance under the output directory.

Focused adapter tests: `test_runner.ps1`, `test_compare.ps1`,
`test_progress.ps1`, `test_provenance.ps1`, and `test_corpus.ps1`.
